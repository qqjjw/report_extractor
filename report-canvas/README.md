# DART 보고서 무한 캔버스

기존 수집 앱과 독립적으로 실행하는 Electron 앱입니다. 상위 폴더의 `data/reports.json`에 기록된 모든 DART 보고서를 실제 웹 화면으로 열어 가로 캔버스에 배치합니다.

## 실행

캔버스 외에 비표시 웹 화면 하나를 유지하는 **CLI 세션**도 제공합니다. CLI는 기존 `../data/reports.json`의 보고서만 처리하며, 실행 중 캔버스의 선택 목록과 연결되지 않습니다. 전체 보고서를 자동 검색하거나 AI 모델을 호출하지 않습니다.

Node.js 22 이상에서 이 `report-canvas` 폴더를 터미널로 열고 실행하세요.

```powershell
npm install
npm start
```

설치 후 `start.cmd`를 더블클릭해도 됩니다. 수집 앱을 동시에 실행할 필요는 없지만 `../data/reports.json` 파일은 필요합니다. 별도 설정 파일이나 파일 선택 단계는 없습니다.

## CLI 세션 사용법

이 폴더에서 `npm run cli` 또는 `node cli.js`를 실행하고 JSON 한 줄씩 입력합니다. AI·다른 코드에서 호출할 때는 npm 안내 문구가 없는 **`node cli.js`**를 사용하세요. 직접 실행한 CLI의 stdout은 JSON 응답만 출력하며 Electron 진단은 stderr로 보냅니다. 내부 Windows named pipe로 Electron과 통신하지만 HTTP 서버나 포트를 열지는 않습니다.

```json
{"id":"1","command":"reports"}
{"id":"2","command":"toc","params":{"rcpNo":"20240312000736"}}
```

접수번호는 자신의 목록에 있는 값으로 바꾸세요. 응답은 `{"id":"1","ok":true,"result":...}` 또는 `{"id":"1","ok":false,"error":{"code":"...","message":"..."}}` 형식입니다. 명령은 순차 처리하며 실패한 명령 뒤에도 다음 명령을 처리합니다. 잘못된 JSON의 응답 ID는 `null`입니다.

| command | params와 결과 |
| --- | --- |
| `reports` | 인자 없음. 목록을 다시 읽어 보고서 정보와 대상 `year`를 반환. 기간 없으면 year는 null |
| `toc` | `rcpNo`. 목차의 `id`, `title`, `path`, `doc`, `bodyUrl` 배열 반환 |
| `find` | `rcpNo`, `node`(toc의 항목), `section`, `keywords` 배열 또는 쉼표·줄바꿈 문자열. `offset` 기본 0, `limit` 기본 20·최대 100 |
| `read` | `locator`(find의 후보 항목). 위치·내용 지문을 재확인해 셀과 병합 정보 반환 |
| `export` | `manifestPath`, `.xlsx` `outputPath`. 기존 파일을 바꾸려면 `overwrite: true` 필수 |
| `close` | 종료 응답 후 웹 화면과 프로세스 종료. 입력 EOF도 대기 중 명령을 처리한 뒤 종료 |

`find`의 검색 문구는 AND 조건이며 공백과 대소문자를 무시합니다. 구간 제목과 다음 제목 사이에서 검색하고, 경계가 불분명하면 오류를 반환합니다. 세부 목차 자체를 검색할 때는 `section`에 그 목차의 `title`을 사용하세요. 현재 본문 전체를 검색하려면 **`broad: true`**를 명시해야 합니다. 다른 보고서나 목차를 자동 순회하지 않습니다.

검색 결과는 `{total, offset, limit, nextOffset, candidates}`입니다. 각 후보는 `rcpNo`, `node`, `bodyUrl`, `index`, `fingerprint`, `rowCount`, `columnCount`, `preview`를 포함하는 locator입니다. 미리보기는 최대 3행×4열이고 전문은 없습니다. 다음 요청에서 이 후보 객체를 그대로 `locator`로 사용하세요. `read`의 `cells`는 0부터 시작하는 `r`, `c`, `rs`(rowspan), `cs`(colspan), `text`, `header`를 제공합니다.

### CLI 엑셀 저장

호출자가 검색 결과 중 원하는 표를 골라 다음 구조의 JSON 파일을 만듭니다. 아래 `locator` 자리에는 find의 후보 객체 전체를 넣어야 합니다.

```json
{"version":1,"tables":[{"locator":{"rcpNo":"...","node":{},"bodyUrl":"...","index":0,"fingerprint":"...","rowCount":1,"columnCount":1,"preview":[]},"group":1,"year":2023}]}
```

```json
{"id":"3","command":"export","params":{"manifestPath":"C:/work/chosen.json","outputPath":"C:/work/result.xlsx"}}
{"id":"4","command":"close"}
```

연도는 보고서명의 대상 기간에서 알 수 있으면 생략할 수 있고, 기간이 없으면 필수입니다. 그룹은 양의 정수이며 배열 순서가 선택 순서입니다. 파일 경로는 CLI를 시작한 작업 디렉터리를 기준으로 해석합니다. 입력 JSON과 원본 목록은 수정하지 않습니다.

기존 캔버스와 같은 연도 열 블록·그룹 행 배치·셀 순서·병합·숫자 표시·원문 링크를 사용합니다. 표를 하나의 웹 화면에서 순차적으로 재확인하고 그룹 단위로 저장합니다. 원문 변경·읽기 실패 시 오류에 실패한 `locator`를 포함하고 전체 저장을 중단합니다. 임시 파일을 완성한 뒤 게시하며, 기본값에서는 기존 파일을 원자적으로 보호합니다. 출력 폴더는 미리 만들어 두세요.

### 다른 Node.js 코드에서 호출

다음 예제 파일을 이 폴더에 두고 실행하면 목록 조회 후 정상 종료합니다. 같은 `ask()` 함수로 toc → find → read → export를 호출할 수 있습니다.

```javascript
const {spawn} = require('node:child_process');
const readline = require('node:readline');
const child = spawn(process.execPath, ['cli.js'], {cwd: __dirname});
const waiting = new Map();
let number = 0;
child.stderr.pipe(process.stderr);
readline.createInterface({input: child.stdout}).on('line', line => {
  const response = JSON.parse(line);
  waiting.get(response.id)?.(response);
  waiting.delete(response.id);
});
function ask(command, params = {}) {
  return new Promise(resolve => {
    const id = String(++number);
    waiting.set(id, resolve);
    child.stdin.write(JSON.stringify({id, command, params}) + '\n');
  });
}
(async () => {
  try {
    const response = await ask('reports');
    if (!response.ok) throw new Error(response.error.message);
    console.log(response.result);
  } finally {
    await ask('close');
    child.stdin.end();
  }
})();
```

호출하는 실제 서비스에서는 프로세스 오류·예상치 못한 종료 시 대기 요청을 실패 처리하고 호출 제한 시간을 설정하세요. AI 도구는 이 JSONL 인터페이스를 감싸 사용할 수 있으며 MCP 서버는 포함하지 않습니다.

CLI도 Chromium을 실행하므로 메모리가 0에 가깝지는 않습니다. 현재 Windows 환경에서 2023년 목차 조회 직후 Node 실행기와 Electron 자식 프로세스 전체의 Private Memory는 약 **191MB**로 한 번 측정했습니다. 이는 최대 사용량이나 캔버스 대비 절감률이 아니며 본문·내보내기·환경에 따라 달라집니다. 세션 종료 때 브라우저를 닫고, 보고서마다 새 웹 화면을 누적하지 않습니다.

CLI 통신·명령은 `cli.js`, `cli-worker.js`, 공통 접속 설정은 `lib/browser.js`, 목차·검색·표 읽기는 `lib/toc.js`, `lib/tables.js`, `lib/selection.js`, Excel은 `lib/excel.js`에서 확인합니다.

## 사용법

- 최초 실행: JSON 순서대로 1,060×1,400 크기의 보고서를 가로 한 줄로 엽니다.
- 빈 공간 드래그: 캔버스를 상하좌우로 이동합니다.
- 제목 표시줄 드래그: 보고서를 원하는 위치로 옮깁니다.
- 사이트 안: DART 목차 클릭, 본문 스크롤과 링크를 평소처럼 사용합니다.
- 오른쪽 아래 손잡이: 해당 카드의 크기를 조절합니다. 최소 크기는 480×360입니다.
- 이 크기를 전체에 적용: 해당 카드의 너비·높이를 모든 보고서에 적용합니다. 위치는 유지되므로 겹치면 나란히 정렬을 누르세요.
- 나란히 정렬: 현재 순서·각 카드 크기를 유지해 가로 한 줄로 재배치하고 첫 보고서로 이동합니다.
- 기간 ↑ / 기간 ↓: 접수일자가 아닌 보고서명의 `(2025.12)` 같은 대상 연월로 정렬합니다. 같은 기간은 원본 JSON 순서, 기간이 없는 보고서는 마지막입니다.
- − / + / 100%: 캔버스 배율을 25~150%로 조절합니다. 사이트 안의 휠은 본문 스크롤입니다.
- 목록 새로고침: JSON을 다시 읽고 모든 사이트를 처음부터 엽니다. 직접 옮긴 배치·크기·배율은 기본 상태로 돌아갑니다. 파일이 잘못되면 현재 화면은 유지하고 오류를 표시합니다.
- 다시 열기: 특정 보고서의 접속 실패 시 그 사이트만 다시 엽니다.

파일 변경은 새로고침 전까지 반영되지 않습니다. 배치·크기·배율은 저장하지 않습니다. 원본 JSON은 읽기만 하며 앱 종료 시에도 수정하지 않습니다.

## 표 선택·그룹 관리·Excel 저장

1. 보고서 카드의 **표 선택 OFF**를 눌러 ON으로 바꾸고 표를 클릭하세요. 초록 테두리가 생기며 여러 표를 연속 선택할 수 있습니다. 같은 표를 다시 클릭하면 취소합니다. 중첩 표는 가장 안쪽 표를 선택합니다. 검색 기준 선택 모드와는 동시에 켜지지 않습니다.
2. 좌측 **선택 표** 탭에서 보고서별 선택 목록을 펼치세요. 대상 연도, 그룹 번호, 목차 경로, 표 크기와 최대 **3행×4열** 미리보기를 표시합니다. 보고서 목록 탭에도 선택 개수를 표시합니다.
3. 자동 그룹은 연도별 선택 순번입니다. 2023년 첫 표와 2022년 첫 표는 모두 G1, 각 연도의 둘째 표는 G2입니다. 그룹 입력란에서 양의 정수로 바꿀 수 있습니다. 취소하거나 그룹을 바꾸어도 다른 표는 재번호화하지 않습니다. 같은 그룹·같은 연도에 여러 표를 넣어도 됩니다.

   선택 표의 초록 테두리 왼쪽 상단에도 **그룹 G [번호]** 입력란을 표시합니다. 표 선택 OFF 상태에서도 수정할 수 있고 Enter 또는 포커스 이탈 시 반영합니다. Escape는 기존 번호로 되돌립니다. 빈 값·0·음수·소수는 기존 값으로 복원하고 입력란 옆에 이유를 표시합니다. 표 위와 좌측 목록의 번호는 서로 반영되며 엑셀에도 변경된 번호를 사용합니다. 검색·내보내기·원문 이동 중에는 편집을 잠급니다.
4. 연도는 보고서명의 `(2023.12)`에서 읽습니다. 대상 기간이 없는 보고서는 선택 표 탭에서 연도를 먼저 지정하세요. 접수 연도를 대신 사용하지 않습니다.
5. **원문 보기**로 해당 보고서·목차를 열고 선택 표로 이동합니다. 위치와 내용 지문이 달라지면 다른 표로 대체하지 않고 재선택을 안내합니다. **선택 취소**는 목록과 초록 표시를 제거합니다.
6. **선택 표 엑셀 저장**을 누르고 Windows 저장 대화상자에서 `.xlsx` 저장 위치를 지정하세요. 검색·원문 이동·내보내기 작업 중에는 선택과 그룹 변경을 잠시 막습니다.

선택한 표는 **단일 시트**에 저장합니다. 연도는 왼쪽부터 오름차순, 그룹은 위에서 아래로 번호순입니다. 같은 그룹은 서로 다른 연도에서도 같은 시작 행에 놓으며 가장 높은 연도 영역에 맞춰 다음 그룹을 배치합니다. 연도별 열 폭은 해당 연도의 가장 넓은 표를 수용하도록 확보합니다. 같은 연도·그룹의 표는 선택 순서대로 세로로 쌓고, 없는 영역은 비워 둡니다.

표 위에는 그룹·보고서명·목차·원문 링크를 표시합니다. 원본 행·열 순서, 셀 텍스트, rowspan·colspan 병합을 유지합니다. 명확한 숫자는 숫자로 저장하고 천 단위·소수점·음수 괄호 형식을 유지합니다. 대시, 선행 0 식별번호, 긴 번호와 애매한 표현은 문자열로 보존합니다. 수식처럼 보이는 원문도 수식으로 실행하지 않습니다. 개별 항목 매칭·행 정렬·단위 환산은 하지 않습니다.

선택 목록에는 표 전문이나 HTML을 복사해 두지 않습니다. 주소·목차·표 위치·내용 지문·크기·짧은 미리보기만 보관합니다. 내보내기 때 표를 다시 확인하고 셀을 읽습니다. 다른 목차에 있는 표는 별도 임시 웹 화면 **하나**에서 순차적으로 읽어 현재 보고서의 목차와 스크롤을 유지합니다. 셀 데이터는 그룹 단위로 쓰고 해제합니다. 생성 중에는 임시 파일을 사용하며, 원문 확인이나 읽기 실패 시 해당 표에 오류를 표시하고 전체 저장을 중단합니다. 기존 완료 파일을 부분 결과로 덮어쓰지 않습니다.

목차를 바꾸어도 선택·그룹은 유지하고 해당 본문을 다시 열면 초록 표시를 복원합니다. 앱 종료와 성공한 목록 새로고침 시 선택·그룹·수동 지정 연도를 초기화합니다. 잘못된 JSON으로 새로고침에 실패하면 현재 선택도 유지합니다. 원본 `reports.json`에는 쓰지 않습니다.

| 문제 | 먼저 확인할 코드 |
| --- | --- |
| 수동 클릭·중첩 표·초록 표시·표 위 그룹 입력·원문 지문 확인 | `lib/selection.js`의 본문 DOM 처리 |
| 연도·자동 그룹·중복 선택 | `lib/selection.js`의 `reportYear()`, `SelectionList` |
| 목차 이동 후 복원·그룹 이벤트 반영·편집 잠금·임시 원문 읽기 | `main.js`의 `syncFrame()`, `handleGroupEvents()`, `updateEditingControls()`, `exportSelections()` |
| 연도 열·그룹 행·병합·숫자 형식·파일 교체 | `lib/excel.js`의 `layout()`, `cellValue()`, `writeSelections()` |
| 탭·미리보기·그룹 입력·버튼 | `renderer.js`, `card.js`, HTML·CSS |

자동 검증은 다중 선택·그룹 배치·누락 연도·병합·문자열 안전성·저장 실패 보호를 포함합니다. 실제 DART와 제공된 2022·2023년 HTML에서도 표를 읽어 Excel 파일을 생성하고 다시 읽어 확인합니다.

## 자원 사용과 제한

사이트는 최초에 최대 3개씩 동시에 불러오며, 화면 밖에 있어도 닫지 않습니다. 보고서 수가 많으면 메모리 사용량과 첫 로딩 시간이 증가합니다. 모든 로드가 끝난 뒤 목록 새로고침을 사용할 수 있습니다. 일부 보고서 접속 실패는 다른 보고서 사용을 막지 않습니다. DART의 팝업은 별도 창으로 열릴 수 있습니다.

선택한 원본 표의 Excel 내보내기를 지원합니다. 개별 항목 매칭·행 재배열·단위 환산, 전체 보기와 배치 저장은 포함하지 않습니다.

기존 파일의 상단 입력값과 처리 로직을 한국어 주석으로 나눕니다. 상시 상세 로그는 남기지 않습니다. 문제가 생겼을 때 실제 요청과 응답을 확인하고 관련 코드를 점검합니다.

## 문제 해결과 검증

- 파일 없음: 수집 앱에서 보고서 목록을 저장하고 `main.js`의 `REPORTS_FILE`을 확인하세요.
- JSON 형식 오류: 수집 앱의 version 1 저장 형식과 필수 필드를 확인하세요. 새로고침 실패는 현재 화면을 닫지 않습니다.
- DART 접속 실패: 해당 카드에서 다시 열기를 누르고 일반 브라우저 접속도 확인하세요. 실제 앱 이름이 요청에 포함되는 문제는 User-Agent에서 앱 이름·Electron 제품명을 제거하여 대응합니다.
- 기간 순서 이상: 보고서명과 `lib/scene.js`의 `PERIOD_PATTERN`을 확인하세요. 접수일자로 정렬하지 않습니다.
- 이동·크기·사이트 배율 이상: `main.js`의 `layout()`과 제스처 처리를 확인하세요.

```powershell
npm test
```

실제 접속 확인은 스크립트로 main.js만 불러오는 대신 `npm start`와 같은 패키지 진입점으로 수행하세요. 검증용 `work/`와 `node_modules/`는 Git 대상에서 제외됩니다.

### 캔버스 스크롤바와 보고서 목록

캔버스 하단 가로 스크롤바와 오른쪽 세로 스크롤바로 전체 시점을 이동합니다. 보고서 내부 스크롤은 해당 사이트만 이동합니다. 빈 공간 드래그도 같은 캔버스 시점을 조작합니다.

좌측 목록에서 보고서를 누르면 현재 배율과 크기를 유지하며 보고서 중심으로 이동하고, 겹친 보고서는 앞으로 가져옵니다. 회사명·보고서명·접수일자·로딩 상태를 확인할 수 있습니다. 상단 **목록 접기 / 펼치기** 버튼과 패널 오른쪽 경계선 드래그로 표시 및 폭을 조절합니다. 기본 폭은 280px이며 200~500px 범위에서 캔버스 공간을 400px 이상 남깁니다. 패널을 조절하거나 창 크기를 바꿔도 보던 캔버스 중심과 사이트 상태는 유지됩니다.

목록 새로고침은 선택을 초기화하고 모든 사이트를 다시 엽니다. 현재 실행 중의 패널 폭과 접힘 상태는 유지하지만 재실행 시에는 저장되지 않습니다. 스크롤바 이동은 현재 범위 안에서 멈춥니다. 빈 공간 드래그는 무한 이동을 유지하며, 화면이 경계를 벗어날 때만 범위를 확장합니다. 보고서 이동·크기 변경은 보고서 주변 화면 한 개만큼의 여유를 반영하고, 정렬·배율 변경·새로고침 시 범위를 다시 계산합니다.

| 증상 | 확인할 코드 |
| --- | --- |
| 스크롤 범위·음수 좌표·중앙 이동 오류 | `report-canvas/lib/scene.js`의 경계·범위·중앙 계산 |
| 패널 폭·화면 중심·웹 화면 겹침 오류 | `report-canvas/main.js`의 패널 입력값과 layout |
| 목록 순서·선택·스크롤바 표시 오류 | `report-canvas/renderer.js`, `index.html`, `style.css` |
| 패널 드래그·화면 통신 오류 | `report-canvas/preload.js`, `overlay.js`, `main.js` |

새로고침은 도구 모음 오른쪽의 경고 색상 버튼을 **1.5초 동안 누르고 있어야** 실행됩니다. 하단 진행 표시가 완료되기 전에 놓거나 버튼 밖으로 이동하면 취소합니다. 키보드 Space·Enter도 같은 방식이며, 포커스를 잃으면 취소합니다. 새로고침은 모든 사이트의 진행 상태와 배치·크기·배율을 초기화합니다. 누르기 시간과 보호 동작은 `report-canvas/renderer.js`, 버튼 배치는 HTML·CSS, 스크롤 범위는 `report-canvas/lib/scene.js`와 `main.js`에서 확인합니다.

### 기준 표 선택과 다른 보고서의 표 찾기

1. 기준 보고서에서 원하는 표를 열고 카드 하단의 **검색 기준 선택**을 누른 뒤 본문 표를 클릭합니다. 기준 표에는 보라색 테두리가 생깁니다. 선택 모드에서 다시 버튼을 누르면 취소합니다.
2. 좌측에 나타난 검색 조건에서 **세부 구간명**을 확인합니다. 가까운 소제목을 제안하지만, 잘못 잡혔다면 `유형자산`처럼 원하는 구간 제목으로 수정하세요. 기준 표가 열린 목차 경로도 표시됩니다.
3. 기준 표의 셀 문구 버튼을 누르거나 **필수 문구**를 입력합니다. 예를 들어 `감가상각비`, `기초`, `기말`을 한 줄씩 입력하면 세 문구를 모두 포함한 표만 찾습니다. 문구는 기준 표 안에 실제로 있어야 합니다. 공백과 대소문자는 무시하고 줄바꿈·쉼표로 구분합니다. 연도·금액보다 항목명을 사용하면 연도별 표기 차이에 대응하기 쉽습니다.
4. 좌측 체크박스로 다른 보고서를 선택하고 **선택한 보고서에서 찾기**를 누릅니다. 카드의 **이 표로 검색**을 사용하려면 먼저 **조건 저장**을 누르세요. 기준 보고서는 대상에서 제외합니다.
5. 대상의 첫 후보 표로 자동 스크롤하고 파란 테두리를 표시합니다. 목차 이동 직후 레이아웃과 사이트의 초기 스크롤 처리를 짧게 재확인하므로 별도의 현재 구간 검색을 누를 필요가 없습니다. 내용을 확인해 **합격** 또는 **불합격·다음 표**를 누릅니다. 거절한 표는 같은 후보 목록에서 다시 시도하지 않습니다. 합격 판정으로 저장용 선택 목록에 자동 추가되지는 않습니다.

검색은 기준 표가 열린 목차에서 시작합니다. 번호·공백·구두점 차이를 정리한 정확한 제목으로 대상 목차를 찾고, 세부 목차가 없으면 정확히 일치하는 상위 목차를 엽니다. 같은 제목은 상위 경로로 구분하며 모호하면 자동 이동을 중단합니다. 공통 단어만으로 다른 목차를 선택하는 이전 탐색 방식은 제거했습니다.

열린 본문에서 세부 구간 제목과 다음 같은 수준 이상의 제목 사이에 있는 표만 검색합니다. 연결/별도 구분은 목차 경로에서 유지하고 본문 구간명 끝의 `(연결)`·`(별도)` 표기 차이를 정리합니다. 목차 자체가 지정한 세부 구간이면 열린 본문 끝까지 사용할 수 있습니다. 제목이 없거나 반복되거나 구간 끝을 확인하지 못하면 **범위 확인 필요**로 표시하고 자동으로 주석 전체를 검색하지 않습니다.

- **현재 구간에서 검색**: 사람이 대상 목차를 직접 연 뒤 그 본문에서 세부 구간과 필수 문구를 다시 검색합니다.
- **현재 구간 전체 검색**: 세부 구간 제한을 명시적으로 해제하고 현재 열린 본문의 모든 표에서 필수 문구를 찾습니다. 보고서 전체를 자동 순회하지 않습니다.
- **후보 다시 표시**: 현재 후보를 다시 파란 테두리로 표시합니다. 다른 목차로 이동했다면 현재 구간에서 다시 검색하세요.

구간명이나 검색 문구를 바꾸어 새 검색을 시작하면 확인 후 이전 판정·제외 기록을 초기화합니다. 기준 표를 새로 선택해도 검색 판정은 초기화하지만 수동 선택한 표는 유지합니다. 기준 본문을 바꾼 경우 검색 기준을 다시 선택해야 합니다. 대상 체크 변경은 다음 검색에 반영됩니다. 기록은 실행 중 메모리에만 두며 원본 JSON에 쓰지 않습니다.

Ctrl+F 키를 흉내 내는 방식이 아닙니다. 브라우저에 이미 열린 본문의 DOM에서 구간 제목과 표 텍스트를 읽어 문자열을 비교합니다. 기준 표의 텍스트·셀 문구와 후보의 위치·짧은 미리보기만 앱에 전달합니다. 보고서 전체 텍스트를 미리 모으거나 상시 분석·AI 추론을 하지 않습니다. 대상은 순차적으로 처리하며 매우 큰 주석 본문이나 표가 많으면 검색 시간이 늘 수 있습니다. 중첩 표는 가장 안쪽 표 단위로 선택·검색합니다.

같은 문구가 들어 있어도 당기/전기 또는 표의 의미가 다를 수 있습니다. 검색은 후보를 제시하는 단순한 1차 로직이므로 사람이 내용을 확인해야 합니다. 수동 선택한 표의 초록 테두리는 보라색·파란색보다 우선합니다.
