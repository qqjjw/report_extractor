# DART 개인용 캔버스

최종 개정: 2026-10-24

## 왜 이 방식을 고안했는가

AI가 긴 문서 전체를 미리 임베딩하거나 많은 원문을 반복해서 읽으면 처리 비용과 토큰 사용량이 커질 수 있습니다. 사람이 목차와 제목으로 위치를 좁히고 필요한 부분만 읽는 과정에서 출발했습니다. **핵심은 전체 문서를 임베딩하지 않는 것입니다.**

**검색 목표 파악 → 저비용 리트리벌 → 후보 축소 → 필요한 후보만 임베딩 → 대응 표 선정**

목차·제목·키워드·문서 구조로 후보를 먼저 찾습니다. 후보가 많으면 검색 조건부터 조정하고, 단일 후보라면 임베딩을 생략할 수 있습니다. 유사도만으로 표의 의미를 확정하지 않으며 연결·별도, 당기·전기, 행·열의 의미는 AI가 원문을 읽고 판단합니다.

범용 흐름은 **Core**, DART의 목차·본문 iframe·HTML 표 접근은 **Profile**로 분리합니다. 현재 기본 검색은 **문자열 기반**이고, 임베딩 서버를 설정했을 때만 선별 후보의 벡터 비교를 실행합니다.

## 1. 현재 기능과 실행

사람과 AI가 **같은 Electron 창**에서 DART 보고서를 탐색하는 개인용 실험 앱입니다. 앱 안에 대화형 AI를 내장하지 않았으며, 이 대화의 AI가 로컬 명령으로 조작합니다. 배포 기능·DB·추가 UI 프레임워크·별도 스킬은 만들지 않습니다.

- reports.json의 보고서를 모두 엽니다. 현재 입력은 삼성전자 2016~2025년 사업보고서 10개입니다.
- 이동·크기 조절 가능한 보고서 창, 확장되는 캔버스, 보고서 목록과 접수일 정렬, 좌우 패널을 제공합니다.
- 사람이 선택한 기준 표를 바탕으로 다른 보고서를 검색하고, 여러 차례 검색한 표를 누적 선택할 수 있습니다.
- 선택한 표를 원문 서식에 가깝게 Excel 한 시트로 저장합니다. 자동 해시 대조·조건 검증·저장 후 XLSX 재검증은 수행하지 않습니다.

    npm install
    npm start

설치 후 start.cmd를 더블클릭해도 됩니다. DART 원문은 실시간으로 불러오므로 유선 또는 Wi-Fi 인터넷 연결이 필요합니다. 보고서 전체를 오프라인 보관하는 기능은 없습니다.

기본 배치는 **가로 한 줄**, 창당 **1152×1520**, 간격 **24**, 캔버스 **60%**, 사이트 **100%**입니다. 배치·기준 표·검색 결과·누적 선택·임베딩 캐시는 실행 중 메모리에서 유지하며 종료하면 사라집니다. Electron의 일반 브라우저 캐시는 별도로 존재합니다.

## 2. 사람의 사용법

### 표 찾기와 선택

1. 왼쪽 보고서를 누르면 카메라가 이동하고 창이 앞으로 나옵니다.
2. 오른쪽 **기준 표 선택**을 누른 뒤 원문의 표를 클릭합니다.
3. 대화에서 “선택한 표를 다른 보고서에서도 찾아줘”라고 요청합니다.
4. AI가 대응 표가 있는 보고서와 목차로 이동하고 본문을 스크롤합니다.
5. 여러 표를 모으려면 **표 종류**를 입력하고 **이 표를 목록에 추가** 또는 **기준 표를 목록에 추가**를 누릅니다.

표 클릭만으로 AI에게 대화가 전송되거나 검색이 시작되지는 않습니다. 기준 표는 다른 보고서를 눌러도 유지됩니다. **기준 표로 이동**과 **해제**로 관리합니다.

| 테두리 | 역할 |
|---|---|
| 파랑 | 사람 또는 AI가 지정한 기준 표 |
| 주황 | 검색 결과로 선택한 표 |

표 전체에 사각 테두리를 표시합니다. 셀·행을 노랗게 칠하지 않으며, 같은 표가 두 역할이면 파랑을 우선합니다.

### 캔버스·배율·패널

- 제목을 잡아 창을 옮기고, 테두리·모서리로 크기를 조절합니다. 클릭한 창이 앞으로 나옵니다.
- 캔버스의 가로·세로 스크롤바로 이동합니다. 창이나 카메라가 가장자리에 접근하면 작업 영역을 확장합니다.
- 빈 공간의 **Ctrl+휠**과 상단 **− / 배율 / +**는 캔버스를, 사이트 내부의 Ctrl+휠과 창별 버튼은 해당 사이트 내용만 조절합니다. 일반 휠은 사이트를 스크롤합니다.
- 캔버스는 50~200%, 사이트는 50~250%입니다. 버튼은 10%p씩 변경하고 배율 표시를 누르면 100%로 복원합니다.
- 왼쪽은 보고서 목록·정렬, 오른쪽은 기준 표·검색·선택 목록·로그입니다. 안쪽 경계로 너비를 바꾸고 위쪽 화살표로 접습니다. 기본 너비는 왼쪽 250px, 오른쪽 300px입니다.
- 접수일 정렬은 receivedDate를 기준으로 창을 가로 재배치합니다. 기본은 내림차순이며 창별 크기·사이트 배율은 유지합니다.
- 이동·크기·배율 변경은 문서를 재로딩하지 않습니다. 표를 찾거나 선택할 때 사용자 배율을 바꾸지 않습니다.

### 보고서 다시 불러오기와 접속 오류

**보고서 다시 불러오기**를 1초 연속 누르면 reports.json을 다시 읽습니다. 일찍 놓거나 포인터가 벗어나면 취소하며 탐색 중에는 실행하지 않습니다.

ID·URL이 같으면 기존 창과 상태를 재사용합니다. 추가·삭제·URL 변경 항목만 반영하고, 입력 JSON 오류가 나면 현재 창을 유지합니다. 제거되거나 URL이 바뀐 보고서의 선택 표는 목록에서 제외합니다.

접속 실패는 **검색 결과 0개와 다릅니다.** 해당 보고서의 오류와 다시 시도 버튼을 이용합니다. 본문만 실패하면 해당 iframe을, 바깥 페이지가 실패하면 해당 보고서를 다시 엽니다. 바깥 페이지 로딩 종료만으로 본문 접속을 성공 처리하지 않습니다.

## 3. AI 명령과 검색 절차

### 같은 화면을 조작하는 원칙

AI는 **기존 로컬 제어 명령으로만** 앱을 조작합니다. Computer Use·마우스 자동화·화면 캡처·Excel 미리보기 이미지를 사용하지 않습니다. 필요한 명령이 없으면 최소 명령을 구현합니다.

탐색 시작 시 다음 명령으로 제어 중인 창을 표시합니다.

    node control.cjs app-show
    node control.cjs state
    node control.cjs source-get

app-show는 연결된 Electron 창을 표시하고 앞으로 가져옵니다. 중복 실행은 새 캔버스를 만들지 않고 기존 창을 표시합니다. 앱이 닫혀 있으면 정상 표시 상태로 실행합니다. 숨김 실행에서 명령만 성공했다고 사람이 보고 있다고 판단하지 않습니다.

state는 배치·연결·기준 표·선택 목록·검색 결과 요약을 반환하며 원문 전체를 보내지 않습니다. --report 접수번호 사용을 권장합니다. --target 번호는 정렬·목록 변경의 영향을 받고, 생략하면 활성 보고서를 사용합니다. 기존 --target both는 현재 순서의 첫 두 보고서만 검색합니다.

### 목차 INDEX와 내용 검색

| 입력/인자 | 검색 대상 | 동작 |
|---|---|---|
| 어디에서 / indexQuery | DART jsTree 목차 제목 | 공백·대소문자를 무시한 부분 문자열 검색 |
| 무엇을 / query | 해당 목차 본문의 최상위 HTML 표 | 공백으로 나눈 검색어를 모두 포함하는 AND 검색 |

목차 INDEX는 벡터 색인이 아닙니다. 본문에만 있는 소제목은 목차에서 직접 찾을 수 없으므로 상위 목차에서 표와 주변 문맥을 봅니다. 오른쪽 입력칸은 사람의 수동 검색용이며 AI는 같은 기능을 명령으로 호출합니다.

    node control.cjs toc --report 20260310002820 --query "현금흐름"
    node control.cjs search --report 20260310002820 --indexQuery "현금흐름표 (연결)" --query "감가상각비 법인세" --k 5
    node control.cjs read --report 20260310002820 --id "52:table:4" --query "감가상각비"
    node control.cjs read --report 20260310002820 --id "52:table:4" --full true
    node control.cjs result-show --report 20260310002820 --id "52:table:4"

ID는 반드시 실제 목차·검색 결과에서 얻습니다. 위 ID는 이 보고서 집합의 예시이며 다른 연도에 고정하지 않습니다. read --query는 반환할 행을 좁히는 용도이고 새 검색이 아닙니다. --full true는 셀·병합·서식 구조를 포함해 반환하므로 필요할 때만 사용합니다.

result-show는 알고 있는 위치를 재검색 없이 엽니다. 원문 해시 계산·비교와 --hash 대조는 제거했습니다. 과거 verify 명령은 호환용으로 read와 같은 원문 읽기만 수행하며, 별도 조건 검사나 합격·불합격 판정을 하지 않습니다.

### 목표에서 대응 표까지

1. 사용자가 기준 표를 선택했다면 source-get, 필요한 경우 source-read로 그 표만 읽습니다. 기준을 무시하고 전체 탐색을 다시 시작하지 않습니다.
2. AI가 목차명·행·열·주변 문맥에서 검색 단서를 정합니다.
3. 목차를 찾고 해당 범위의 표만 검색합니다. 후보가 많으면 조건을 좁히고, 없으면 다른 명칭·상위 목차·완화된 쿼리로 재시도합니다.
4. AI가 원문을 읽어 목표에 맞는 표와 연결·별도, 당기·전기를 판단합니다. 고정 연도별 목차 번호나 특정 행 이름에 의존하지 않습니다.
5. 나머지 보고서는 한 번의 배치 실행으로 처리하고 요약만 출력합니다. search 자체는 보고서 하나를 대상으로 하며 반복은 AI 또는 호출 코드가 조율합니다.
6. 해당 창으로 카메라를 이동하고, **본문 iframe의 실제 표로 스크롤**한 뒤 전체 테두리를 표시합니다.

position.visible은 본문 프레임과 표가 교차한다는 뜻입니다. 창이 캔버스에서 보이는지, 머리글·요청한 행이 보이는지는 별도로 구분합니다. 표가 크면 필요한 행을 우선 표시하고 배율은 유지합니다. 화면 이동이 안 되었다면 “표 위치는 찾았으나 화면 이동 미완료”라고 알립니다. 이를 자동 무결성 검증과 혼동하지 않습니다.

### 기타 제어 명령

    node control.cjs source-mode --enabled true
    node control.cjs source-select --report 20260310002820 --table 1
    node control.cjs source-select --report 20260310002820 --id "52:table:4"
    node control.cjs source-read
    node control.cjs source-show
    node control.cjs source-clear

--table은 현재 본문의 **0부터 시작하는 최상위 표 번호**입니다. --id는 현재 검색 후보를 사용합니다. source-read는 기준 표 하나만 읽습니다.

    node control.cjs open --report 20260310002820 --id 52
    node control.cjs window-focus --report 20260310002820
    node control.cjs window-raise --report 20260310002820
    node control.cjs window-move --report 20260310002820 --x 1200 --y 0
    node control.cjs window-resize --report 20260310002820 --width 1152 --height 1520
    node control.cjs canvas-pan --x 1200 --y 0
    node control.cjs canvas-zoom --ratio 0.8
    node control.cjs site-zoom --report 20260310002820 --ratio 1.2
    node control.cjs panel-resize --side left --width 250
    node control.cjs panel-toggle --side right --collapsed true
    node control.cjs reports-sort --direction asc
    node control.cjs reports-reload
    node control.cjs report-info --report 20260310002820
    node control.cjs report-retry --report 20260310002820
    node control.cjs report-reload --report 20260310002820

좌표·크기는 캔버스 100% 기준의 논리 좌표이며 음수를 허용합니다. 배율 1은 100%입니다. panel-toggle --collapsed false는 펼치기, reports-sort --direction desc는 내림차순입니다. report-reload는 보고서 페이지 재로딩이고 reports-reload는 JSON 목록 재로딩입니다. canvas-viewport는 렌더러가 화면 크기를 동기화하는 내부 명령입니다.

## 4. 다중 검색·누적 선택과 Excel

### 검색 결과와 선택 목록

보고서별 **검색 결과는 최신 검색으로 교체**됩니다. **선택한 표 목록은 별도로 유지**되므로 1차 주식 수 표를 추가한 뒤 2차 직원 수 표를 추가해 함께 저장할 수 있습니다. 이전 후보 안에서만 재검색하는 필터나 검색 회차별 결과 보관 기능은 없습니다.

    node control.cjs selection-add --report 20260310002820 --id "52:table:4" --group "연결 현금흐름 감가상각비"
    node control.cjs selection-add --report 20260310002820 --source true --group "기준 표"
    node control.cjs selection-list
    node control.cjs selection-read --key "20260310002820/52:table:4"
    node control.cjs selection-show --key "20260310002820/52:table:4"
    node control.cjs selection-refresh --key "20260310002820/52:table:4"
    node control.cjs selection-remove --key "20260310002820/52:table:4"

같은 보고서·표를 다시 추가하면 중복하지 않고 갱신합니다. --source true는 해당 보고서의 기준 표를 추가합니다. selection-show는 저장된 위치로 이동하고, selection-refresh는 그 위치의 현재 원문·서식을 다시 읽습니다. 변경 여부를 해시로 검사하지 않습니다. selection-list는 메타데이터만, selection-read는 표 하나의 메모리 데이터를 반환합니다.

### AI와 스크립트의 역할

**AI는 무엇을 찾을지와 어느 표가 대응하는지를 판단하고, 스크립트는 선택된 원문을 복사합니다.** 스크립트에 특정 회계 항목별 단위·열 이름·색상을 하드코딩하지 않습니다.

- 셀의 표시 문자열·순서·rowspan/colspan을 유지합니다. 쉼표·괄호·대시·줄바꿈을 임의로 숫자 변환·환산·합산하지 않습니다. 양끝 공백은 추출 시 정리합니다.
- DOM에서 얻은 배경색·글자색·글꼴·정렬·테두리를 Excel 지원 범위에서 옮깁니다. AI가 만든 테마·소개문·추정 단위는 넣지 않습니다.
- 표 위 제목·기준일·단위와 작은 메타데이터 표를 함께 가져옵니다. 위로 최대 6개 인접 요소를 읽으며, 앞선 큰 표·번호가 있는 절 제목에서 멈춥니다. 먼 위치의 단위를 추정하거나 미확인 내용을 채우지 않습니다.
- 보고서 이름·출처 URL만 별도 식별 정보로 표시합니다. 계산·설명 추가가 필요하면 사용자가 요청한 범위에서 원문 영역과 분리합니다.

HTML과 Excel의 배치 방식은 다릅니다. 같은 시트의 행 높이·열 너비는 공유하므로 필요한 크기의 최댓값을 사용하며 픽셀 단위의 동일한 외관은 보장하지 않습니다. 모든 CSS 속성이나 멀리 떨어진 주석을 자동으로 옮기는 기능은 아닙니다.

### 저장

AI에게 “선택한 표를 Excel 한 시트로 저장해줘”라고 요청합니다. export-selections.mjs는 앱과 분리된 AI 측 내보내기 코드이며 Electron 시작·검색에 스프레드시트 의존성을 추가하지 않습니다.

    node export-selections.mjs "outputs/새로운_선택표.xlsx"
    node export-selections.mjs "outputs/새로운_현금흐름.xlsx" --group "연결 현금흐름 감가상각비"
    node export-selections.mjs "outputs/새로운_주식_직원.xlsx" --group "주식 수,직원 수"

명령 실행에는 Node를, 파일 작성에는 Codex가 제공하는 Python 런타임의 XlsxWriter를 사용합니다. 원문 데이터는 프로세스 메모리와 표준 입력으로만 전달합니다. 기본 Python 위치는 사용자 홈 아래 .cache/codex-runtimes/codex-primary-runtime/dependencies/python이며 다른 위치라면 DART_PYTHON에 실행 파일 경로를 지정합니다. Electron에 Python이나 추가 npm 패키지를 묶지 않습니다. 검사 로그를 자동 생성하는 저장 도구는 사용하지 않습니다.

한 시트에 종류별로 세로 구역을 나누고, 같은 종류의 표는 보고서명 순으로 정렬해 같은 시작 행에 가로 배치합니다. 현재 사업보고서 이름에서는 연도 오름차순에 해당합니다. 사이트를 재검색하지 않고 선택된 메모리 데이터만 사용합니다. 서식이 없는 오래된 메모리 항목은 selection-refresh로 갱신합니다.

**기존 파일명은 덮어쓰지 않습니다. 새 파일명을 지정합니다.** 새 Excel만 저장하고 파일 경로·표 수·셀 수 등의 요약을 출력합니다. 자동 셀 대조·해시·ZIP/XML 재검증은 실행하지 않으며 검증 완료라는 판정을 출력하지 않습니다.

## 5. 제한과 저장 정책

### Core와 선택적 임베딩

| 후보 상황 | 처리 |
|---|---|
| 목차·표 후보 0개 | 다른 INDEX나 완화한 쿼리로 재시도 |
| 후보가 K 초과 | 원문 반환·임베딩 전에 조건을 좁힘 |
| 후보 1개 | 임베딩 없이 원문 표시 |
| 후보 2~K개, 서버 설정 | 선별 후보만 임베딩해 순위 계산 |
| 후보 2~K개, 서버 미설정 | needs_embedding 반환; AI가 후보를 명시적으로 읽고 선정 |
| 접속 실패 | 후보 0개와 구분하고 해당 보고서만 재시도 |

K의 설계 개념은 비용 정책에 따른 설정값이며, 현재 구현은 기본 5·범위 1~5입니다. 표 하나 16,000자, 검색 후보 합계 24,000자 제한을 사용하며 정확한 토큰 수는 계산하지 않습니다. 현재 대상은 HTML 표이고 PDF·일반 문단 검색과 다른 문서 Profile은 구현하지 않았습니다.

선택적 임베딩은 실행 전 EMBEDDING_URL, 필요하면 EMBEDDING_MODEL·EMBEDDING_API_KEY로 설정합니다. 검색어와 선별 표가 설정한 서버에 전송됩니다. 기본은 외부 호출 없음이며 동일 입력 벡터는 메모리에서 재사용합니다.

    요청: {"input":["검색어","후보1","후보2"],"model":"선택 설정"}
    응답: {"data":[{"index":0,"embedding":[0.1,0.2]},{"index":1,"embedding":[0.3,0.4]},{"index":2,"embedding":[0.5,0.6]}]}

모델을 설정하지 않으면 model 필드를 생략합니다. 입력마다 같은 차원의 벡터가 필요합니다. AI가 표를 읽고 판단한 작업을 벡터 유사도 계산으로 보고하지 않습니다.

### 새 파일과 기존 기록

- 새 원문 HTML·표 데이터·서식·선택 상태를 JSON/JSONL/NDJSON·복구 스냅샷 등으로 저장하지 않습니다. 처리 중 메모리와 로컬 API의 JSON 통신은 파일 저장과 구분합니다.
- 요청된 Excel만 새 추출 산출물로 만듭니다. 캡처·미리보기·manifest·원문 검사 파일은 만들지 않습니다.
- reports.json은 입력, package.json·package-lock.json은 앱 의존성, .local/bridge.json은 제어 포트·토큰 설정입니다. 원문 저장 금지 때문에 제거하지 않습니다.
- .local/search.jsonl에는 쿼리·후보 수·선택 위치·판단·오류 등 원문 없는 경량 이력만 남깁니다. .local/browser에는 Electron의 일반 브라우저 데이터가 있습니다. .local은 Git에서 제외합니다.
- **기존 보조 JSON·과거 결과 Markdown·Excel은 모두 유지합니다.** 당시 기록으로 보관하며 자동 삭제·갱신하지 않습니다. 과거 원문 저장용 임시 스크립트는 재실행을 중단하는 안내를 반환합니다.

## 6. 개발 확인과 과거 사례

코드 변경 후 npm test와 변경 파일의 문법 확인을 실행합니다. 개발 테스트는 앱의 자동 원문·Excel 검증 기능과 별개입니다. 실제 앱 확인은 기존 명령으로만 하고, 마우스 사용성 테스트는 사용자가 수행합니다. 기존 기록은 건드리지 않으며 커밋·푸시는 별도 요청이 있을 때 진행합니다.

다음은 **2026-10-24 당시 삼성전자 보고서 집합에서 수행한 기록**입니다. 현재 성능 보장이나 다른 DART 보고서에 적용할 고정 연도 규칙이 아닙니다.

| 사례 | 당시 접근과 한계 |
|---|---|
| 원재료 표 | 목차 원재료 또는 사업의 내용, 매입액 AND 매입처. 9개 대상 배치 약 14.8초. 최초 기준 읽기·대화·파일 작성 시간 제외. 복수 후보에서 첫 조건 일치 표를 선택했으며 최적 유사도 비교는 하지 않음 |
| 사업부문 요약 재무 | 당시 최종 10개 정상 배치 약 21.57초. 앞선 접속 확인 실패 4회 약 62.42초, 재시도 포함 27회 검색 합계 약 96.04초. 체감 13분의 나머지를 AI 읽기·출력 중 하나로 단정할 수 없음 |
| 주식 수·직원 수 | 각 10개 표를 차례로 선택해 두 종류를 함께 보관·추출. 초기 임의 설명·서식 이후 원문 서식 방식으로 변경 |
| 연결현금흐름 감가상각비 | 최근 보고서는 현금흐름표 (연결) 세부 목차, 이전 보고서는 연결재무제표 주석에서 탐색. 당기·전기 분리 여부와 번호가 붙은 행 이름을 AI가 판단 |

과거 결과 문서와 JSON에는 당시 해시·검증 기록이 남아 있을 수 있습니다. 현재 기능과 구분해 읽습니다. 현재 본문 이동은 150ms 폴링과 성공 후 400ms 대기를 사용하며, 매 검색마다 앱을 빌드하지 않습니다. 중복 탐색·원문 출력·실패 보고서 전체 재로딩을 줄이는 것이 우선입니다.
