# DART 개인용 캔버스

최종 개정: 2026-10-24

사람과 AI가 **같은 Electron 화면에서 DART 보고서를 탐색하는 개인용 실험 앱**입니다. 사람이 원하는 표를 선택하면 AI가 그 표에서 단서를 얻어 다른 보고서의 대응 표를 찾습니다.

배포용 제품은 아닙니다. Electron 외 별도 UI 프레임워크·DB·배포 도구를 추가하지 않습니다. 앱 내부에 대화형 AI를 내장하지 않았으며, 현재 대화의 AI가 로컬 제어 통로로 앱을 조작합니다. 스킬은 아직 만들지 않았습니다.

## 1. 실행과 기본 조건

최초 설치 후 실행:

```powershell
npm install
npm start
```

설치가 끝났다면 `start.cmd`를 더블클릭해도 됩니다. `reports.json`의 보고서를 모두 엽니다. 현재 파일에는 삼성전자 사업보고서 10개(2025~2016년)가 있습니다.

- DART 원문을 실시간으로 불러오므로 **인터넷 연결이 필요합니다.** Wi-Fi 전용은 아니며 유선 인터넷도 가능합니다.
- 전체 보고서를 오프라인 저장하는 기능은 없습니다. Electron과 열어 둔 웹페이지 자체의 디스크·메모리 비용은 발생합니다.
- 기본 배치는 가로 한 줄이며, 창 크기 1152×1520, 창 간격 24, 캔버스 배율 60%, 사이트 배율 100%입니다.
- 일반 실행에서는 배치와 선택 상태를 실행 중에만 유지합니다. 앱을 종료하고 다시 켜면 기본 배치로 시작합니다.

## 2. 사람의 사용법

### 기본 흐름

1. 왼쪽 **보고서 목록**에서 보고서를 누릅니다. 카메라가 해당 창으로 이동하고 창이 앞으로 나옵니다.
2. 원문에서 기준으로 삼을 표를 찾습니다. 위치를 모르면 AI에게 원하는 내용만 설명해도 됩니다.
3. 오른쪽 **기준 표 선택**을 누른 뒤 원문 안의 표를 클릭합니다. 선택 모드는 자동 종료됩니다.
4. 대화에서 **“지금 선택한 표를 다른 보고서에서도 찾아줘”**라고 요청합니다.
5. AI가 대응 표를 찾아 각 보고서를 이동·스크롤하고 결과 테두리를 표시합니다.

표 선택만으로 대화가 자동 전송되거나 AI 검색이 시작되지는 않습니다. 다른 보고서를 클릭해도 기준 표는 유지됩니다. **기준 표로 이동**으로 다시 보여줄 수 있고, **해제**로 선택을 지울 수 있습니다.

| 표시 | 의미 |
|---|---|
| 파란 사각 테두리 | 사람이 선택하거나 AI가 지정한 기준 표 |
| 주황 사각 테두리 | 검색 결과로 선택한 표 |

테두리는 **표 전체**를 둘러쌉니다. 셀·행에 노란 배경을 칠하지 않습니다. 동일한 표가 두 역할을 가지면 파랑을 우선합니다.

### 캔버스와 패널

- 창 제목을 잡으면 이동하고, 테두리·모서리를 잡으면 크기를 조절합니다. 클릭한 창이 앞으로 나옵니다.
- 캔버스의 가로·세로 스크롤바로 이동합니다. 창이나 카메라가 작업 영역 끝으로 가면 해당 방향으로 영역을 확장합니다.
- **캔버스 빈 공간의 Ctrl+휠**과 상단 `− / 배율 / +`는 전체 캔버스를 조절합니다.
- **사이트 내부의 Ctrl+휠**과 창별 버튼은 해당 사이트 내용만 조절합니다. 일반 휠은 사이트 본문을 스크롤합니다.
- 캔버스는 50~200%, 사이트는 50~250%입니다. 버튼은 10%p씩 변경하고 배율 숫자를 누르면 100%로 복원합니다.
- 좌측은 **보고서 목록·정렬**, 우측은 **기준 표·검색·결과·로그**입니다. 안쪽 경계를 잡아 너비를 조절하고 위쪽 화살표로 접거나 펼칩니다. 기본 너비는 좌측 250px, 우측 300px입니다.
- 정렬 기준은 JSON의 `receivedDate`(접수일)입니다. 오름차순·내림차순 정렬 시 창도 가로로 재배치하며 창별 크기·사이트 배율을 유지합니다. 기본은 내림차순입니다.
- 이동·크기 변경·확대는 문서를 재로딩하지 않습니다. 표를 찾거나 선택해도 사용자가 정한 배율을 바꾸지 않습니다.

### 보고서 다시 불러오기와 접속 오류

**보고서 다시 불러오기**를 1초간 누르면 JSON을 다시 읽습니다. 일찍 놓거나 버튼 밖으로 나가면 취소됩니다. 검색 중에는 실행할 수 없습니다.

ID와 URL이 같은 보고서는 기존 창·배율·검색 결과를 유지합니다. 추가 보고서는 오른쪽에 이어 붙이고, 제거된 보고서는 닫습니다. URL이 바뀐 항목은 다시 엽니다. JSON 해석 실패 시 현재 화면을 유지합니다.

접속 실패 시 해당 창에 원인과 **다시 시도** 버튼을 표시합니다. 본문 실패는 해당 iframe만 다시 불러오며, 바깥 보고서 페이지 자체가 실패한 경우에는 해당 보고서를 다시 엽니다. 목록에서도 연결 중·연결됨·접속 오류를 구분합니다.

본문 iframe이 실패했는데 바깥 페이지의 로딩이 끝났다는 이유만으로 성공 처리하지 않습니다. 오류는 실제 본문의 정상 로딩을 확인한 뒤 해제합니다. 연결이 불안정할 때 전체 앱이나 JSON을 반복 재로딩하지 말고 실패한 보고서만 재시도합니다.

## 3. 목차 INDEX와 내용 검색의 실제 의미

오른쪽의 두 입력칸은 **사람이 직접 검색할 때 쓰는 수동 UI**입니다. AI는 같은 기능을 제어 명령으로 호출하므로 이 칸을 직접 채울 필요가 없습니다.

| 입력/인자 | 스크립트가 검색하는 대상 | 예시 |
|---|---|---|
| 어디에서 · 목차 INDEX / `indexQuery` | DART가 제공하는 목차 트리의 제목 | `원재료` → `3. 원재료 및 생산설비` |
| 무엇을 · 공백은 AND / `query` | 선택한 목차 본문 안의 HTML 표 텍스트 | `매입액 매입처` → 두 단어가 모두 있는 표 |

목차 INDEX는 별도로 만든 벡터 색인이 아닙니다. 앱이 DART의 jsTree 목차를 읽어 **공백을 무시한 부분 문자열 검색**을 수행합니다. 내용 검색도 표별 문자열 검색이며 공백으로 나눈 단어를 모두 포함해야 합니다. 현재 일반 검색은 키워드 기반이며, 자동 의미 검색과 같지 않습니다.

`가. 주요 원재료 현황`처럼 본문에만 있는 소제목은 목차 INDEX에서 직접 찾을 수 없습니다. 상위 목차를 찾은 뒤 그 본문에서 표와 주변 문맥을 확인합니다.

**역할 분담:** AI는 목표를 해석하고 쿼리·재시도 전략·검증 조건을 정합니다. 스크립트는 목차 조회, 문자열 검색, 후보 수 제한, 원문 추출, 화면 이동·테두리 표시를 실행합니다.

## 4. AI의 검색 절차와 완료 조건

### 기준 표에서 다른 보고서로

1. `source-get`으로 사용자의 기준 표를 확인합니다. 기준이 있으면 이를 무시하고 전체 탐색부터 다시 시작하지 않습니다.
2. 필요하면 `source-read`로 **그 표 하나만** 읽고 목차명·머리글·행 이름·주변 문맥에서 단서를 얻습니다.
3. 다른 보고서에서 목차 INDEX를 먼저 찾고, 해당 범위의 표만 저비용 검색합니다. 연도별 번호가 같다고 가정하지 않습니다.
4. 같은 목차가 없으면 다른 명칭 또는 상위 목차로 범위를 조정합니다. 기준 표에 있던 품목·공급업체·사업부명을 모든 연도의 필수 조건으로 고정하지 않습니다.
5. 후보 수를 확인한 뒤 필요한 표만 읽고, 소제목·머리글·행·단위·시점 등을 원문으로 검증합니다.
6. 같은 요청의 나머지 보고서는 한 번의 배치 실행으로 처리하고 요약만 반환합니다. `search` 명령 자체는 보고서 하나를 검색하며, 여러 보고서의 반복은 AI 또는 호출 스크립트가 조율합니다.

### 필수 완료 조건: 사람이 찾은 내용을 볼 수 있어야 함

**데이터나 위치를 찾았다는 것만으로 완료로 보고하지 않습니다.**

1. 해당 보고서 창을 앞으로 가져오고 캔버스 카메라를 이동합니다.
2. **DART 본문 iframe 내부의 실제 표 요소로 스크롤합니다.** 캔버스 이동만으로 대신하지 않습니다.
3. 기준은 파랑, 결과는 주황으로 표 전체 테두리를 표시합니다. 원문 값·사용자 배율은 유지합니다.
4. `position.visible`을 확인하고 창이 캔버스에서도 보이는지 함께 확인합니다.
5. 표가 크면 머리글과 요청한 행을 볼 수 있도록 추가로 위치를 확인합니다. 확인하지 못하면 **“위치는 찾았으나 화면 이동 확인은 미완료”**라고 구분합니다.

`position.visible`은 **표 영역이 본문 프레임의 화면과 교차하는지** 나타냅니다. 표 전체·특정 행이 보인다거나 캔버스의 다른 창에 가려지지 않았다는 보장은 아닙니다. 이 값만으로 시각 검증 전체를 대체하지 않습니다. 같은 규칙을 다음 AI 세션용 프로젝트 지침 `AGENTS.md`에도 명시했습니다.

## 5. AI 제어 명령

앱을 실행한 뒤 이 폴더에서 `node control.cjs 명령 --인자 값`으로 호출합니다. 같은 워크스페이스의 다른 AI 세션도 이 파일과 `.local/bridge.json`에 접근해 제어할 수 있습니다. 화면 조작과 문자열 검색에는 별도 AI API 키가 필요하지 않습니다.

보고서는 **`--report 접수번호`**로 지정하는 것을 권장합니다. `--target 0` 같은 번호도 지원하지만 정렬·JSON 변경에 따라 가리키는 보고서가 바뀝니다. 검색 대상을 생략하면 현재 선택한 보고서를 사용하고, 명시적인 `--target both`는 현재 순서의 첫 두 보고서를 검색합니다.

### 상태와 기준 표

```powershell
node control.cjs state
node control.cjs source-get
node control.cjs source-read
node control.cjs source-show
node control.cjs source-mode --enabled true
node control.cjs source-select --report 20260310002820 --table 1
node control.cjs source-clear
```

`state`는 로딩·오류·기준 표·배치·배율·검색 결과 요약을 반환하고 원문 전체는 반환하지 않습니다. `source-get`도 기준 표의 위치·행수·문자수 같은 메타데이터만 반환합니다.

`source-select --table`은 현재 열린 본문의 **0부터 시작하는 최상위 표 번호**입니다. 기존 검색 후보를 기준으로 삼을 때는 `source-select --report ID --id "목차ID:table:번호"`를 사용합니다. `source-read`는 선택한 표 하나를 읽으며 16,000자 제한을 적용합니다.

### 검색·읽기·검증

```powershell
node control.cjs toc --report 20250311001085 --query "원재료"
node control.cjs search --report 20250311001085 --indexQuery "원재료 및 생산설비" --query "매입액 매입처" --k 5
node control.cjs read --report 20250311001085 --id "12:table:1" --query "매입액"
node control.cjs read --report 20250311001085 --id "12:table:1" --full true
node control.cjs verify --report 20250311001085 --term "매입액"
node control.cjs result-show --report 20250311001085 --id "12:table:1"
```

후보 ID는 **먼저 받은 실제 검색 결과에서 선택**합니다. 위 번호는 제공된 삼성전자 보고서의 예시이며 다른 표·보고서에 고정 적용하지 않습니다.

검색 응답은 위치·문맥·머리글·일치 행 위주로 축약합니다. `read --full true`는 rowspan/colspan이 보존된 전체 셀 구조를 반환합니다. `read --query`는 출력할 행을 좁히는 용도이며 새 후보 검색은 아닙니다.

`verify`는 검색어와 선택적 `--year`, `--basis`, `--unit`이 원문에 있는지 확인합니다. 값과 연도 열의 대응, 회계적 적합성까지 자동 확정하지 않습니다.

`result-show`는 이미 확인한 후보 위치를 재검색 없이 다시 보여줍니다. `--hash`를 함께 주면 이전 원문 해시와 다를 때 재검색을 요구합니다.

### 화면·패널·보고서 관리

```powershell
node control.cjs open --report 20250311001085 --id 12
node control.cjs window-focus --report 20250311001085
node control.cjs window-move --report 20250311001085 --x 1200 --y 0
node control.cjs window-resize --report 20250311001085 --width 1152 --height 1520
node control.cjs canvas-pan --x 1200 --y 0
node control.cjs canvas-zoom --ratio 0.8
node control.cjs site-zoom --report 20250311001085 --ratio 1.2
node control.cjs panel-resize --side left --width 320
node control.cjs panel-toggle --side right --collapsed true
node control.cjs panel-toggle --side right --collapsed false
node control.cjs reports-sort --direction asc
node control.cjs reports-sort --direction desc
node control.cjs reports-reload
node control.cjs report-info --report 20250311001085
node control.cjs report-retry --report 20250311001085
```

좌표·크기는 캔버스 100% 기준의 논리 좌표이며 음수 위치도 가능합니다. 배율 `1`은 100%입니다. `canvas-pan`은 화면 왼쪽 위의 좌표를 지정합니다. `open --id`는 `toc`에서 얻은 목차 ID입니다.

`report-info`는 현재 본문 URL·로딩 상태·스크롤 위치 등을 진단합니다. `report-retry`는 실패한 본문만 재시도하고, 필요할 때 `report-reload`로 해당 보고서 페이지 전체를 다시 불러올 수 있습니다. `reports-reload`는 JSON 목록을 다시 읽는 별개의 명령입니다.

사람과 AI는 같은 상태 변경 함수를 사용합니다. 이동 중에는 배치 정보만 전송하며 원문·검색 결과 전체를 반복 전송하지 않습니다. AI가 앱 밖의 사용자 대화를 자동 감시하는 구조는 아닙니다.

## 6. Core + DART Profile과 현재 제한

`core.cjs`는 목표·쿼리 → 저비용 후보 검색 → 개수 판단 → 선택적 임베딩 → 원문 검증의 범용 흐름입니다. `dart-profile.cjs`는 DART 목차·본문 프레임·HTML 표 접근을 담당하며, `main.cjs`가 제어 명령과 경량 로그를 연결합니다.

| 상황 | 기본 처리 |
|---|---|
| 목차 또는 표 후보가 없음 | 다른 INDEX·완화한 쿼리로 재시도 |
| 후보가 K 초과 | 원문 반환·임베딩 전에 쿼리를 좁힘 |
| 후보 1개 | 임베딩 생략, 원문 확인 |
| 후보 2~K개 + 임베딩 서버 설정 | 선택된 표만 임베딩해 순위를 정한 뒤 원문 확인 |
| 후보 2~K개 + 서버 미설정 | `needs_embedding`으로 자동 선정을 중단; AI/호출자가 후보를 명시적으로 읽고 검증 가능 |
| 로딩·네트워크 실패 | 검색 결과 0개와 구분; 해당 보고서만 진단·재시도 |

K는 보고서별 기본 5개, 설정 가능 범위 1~5개입니다. 표 하나 16,000자, 선택 표 합계 24,000자로 제한하며 정확한 토큰 수를 계산하지는 않습니다.

전체 문서 일괄 임베딩은 하지 않습니다. 현재 대상은 HTML 표이며 일반 본문 문단·PDF 검색이나 다른 문서 Profile은 구현하지 않았습니다. 로컬의 선택 표 읽기와 AI의 판단은 의미 유사도 점수 계산과 구분해서 보고합니다.

임베딩 서버가 필요하면 실행 전 `EMBEDDING_URL`, 필요시 `EMBEDDING_MODEL`, `EMBEDDING_API_KEY`를 설정합니다. 설정한 서버로 검색어와 선별 표가 전송됩니다. 동일 입력 벡터는 실행 중 메모리에서 재사용합니다.

```json
{"input":["검색어","후보1","후보2"],"model":"설정한 모델"}
```

```json
{"data":[{"index":0,"embedding":[0.1,0.2]}]}
```

요청/응답 예시이며 모든 입력에 대응하는 벡터가 필요합니다. 모델 미설정 시 요청의 `model` 필드는 생략합니다. 기본값은 외부 임베딩 호출 없음입니다.

## 7. 실제 검색 사례와 속도

### 선택한 원재료 표 검색 — 2026-10-24

2025년 보고서에서 사용자가 선택한 `주요 원재료 현황` 표를 읽고 **목차 `원재료` + 내용 `매입액 AND 매입처`**를 단서로 삼았습니다. 품목·공급업체·금액은 연도별로 달라질 수 있어 필수 조건에서 제외했습니다.

| 대상 보고서 | 사용한 INDEX | 후보 수 |
|---|---|---:|
| 2024~2021년 | 3. 원재료 및 생산설비 | 각 2개 |
| 2020년 | II. 사업의 내용 | 2개 |
| 2019년 | II. 사업의 내용 | 1개 |
| 2018~2017년 | II. 사업의 내용 | 각 2개 |
| 2016년 | II. 사업의 내용 | 1개 |

이 삼성전자 보고서 집합에서는 오래된 보고서의 세부 목차가 없어 상위 목차로 확대했습니다. 모든 DART 보고서에 적용되는 고정 연도 규칙은 아닙니다.

**당시 임베딩 호출은 없었습니다.** 단일 후보 2건은 원문을 확인했습니다. 복수 후보 7건에서는 별도 배치 스크립트가 첫 후보를 읽고 `원재료` 문맥·`매입액`·`매입처`·화면 내 위치가 확인되면 선택하고 중단했습니다. 두 후보를 모두 비교하거나 최적 유사도를 계산하지 않았으므로, **조건에 맞는 대응 표를 확인한 사례**로 해석해야 합니다.

기록된 9개 보고서 배치 구간은 한국 시간 **16:34:27.154~16:34:41.937, 약 14.8초**입니다. 기준 표의 최초 읽기, AI 설명·판단, 결과 문서 작성 시간은 제외한 값이며 향후 속도의 보장은 아닙니다.

### 앞선 약 13분 작업의 병목

사업부문별 요약 재무 현황 탐색 로그에서는 최종 정상 배치 10개가 **약 21.57초**, 앞선 로딩 확인 실패 4회가 **약 62.42초**, 재시도를 포함한 검색 실행 27회 합계가 **약 96.04초**였습니다.

전체 체감 시간에는 반복 검색, AI와 도구의 왕복, 오류 진단·코드 수정·앱 재시작, 긴 표 출력, 결과 파일 작성·정정이 함께 포함됐습니다. AI의 읽기·판단, 답변 생성/표시, 도구 대기, 네트워크와 DOM 처리 시간은 각각 분리 계측하지 않았으므로 나머지 시간을 하나의 원인으로 단정하지 않습니다. 매 검색마다 앱을 빌드하는 단계는 없습니다.

현재 본문 이동 확인에는 150ms 간격의 폴링과 성공 후 400ms 대기가 있습니다. 개선 우선순위는 기준 표 재사용, 한 번의 배치 처리, 중복 원문 출력·재검색 줄이기, 실패한 보고서만 재시도하기입니다. **속도를 이유로 화면 이동 확인을 생략하지 않습니다.**

## 8. 로그·파일·검증

- `.local/search.jsonl`: 쿼리·후보 수·선택 위치·해시·판단·오류 이력. 원문 전체를 복사하지 않습니다.
- `.local/bridge.json`: 실행 중인 로컬 제어 서버의 포트·토큰. 서버는 `127.0.0.1`에서만 수신합니다.
- `.local/browser/`: 브라우저 데이터. `.local/`은 Git 제외 대상입니다.
- 별도 결과 문서/JSON: 요청에 따라 선별한 표의 데이터와 원문 위치를 정리한 산출물이며 경량 실행 로그와 구분합니다.

자동 검증은 `npm test`로 실행합니다. 실제 DART 검증에는 인터넷이 필요합니다. 마우스 사용성 테스트는 사용자가 직접 진행하며 AI는 명령·동작 검증을 수행합니다.
