# DART 보고서 수집과 무한 캔버스

DART에서 필요한 공시보고서 목록을 모으고, 여러 보고서 원문을 가로 캔버스에 펼쳐 비교하는 Windows용 Electron 프로젝트입니다. **목록 수집 앱**과 **보고서 캔버스 앱**은 각각 독립적으로 실행합니다.

| 앱 | 위치 | 역할 |
| --- | --- | --- |
| 목록 수집 | 저장소 루트 | 실제 DART 검색 결과에서 보고서 정보를 모아 JSON으로 저장 |
| 무한 캔버스 | `report-canvas/` | JSON에 기록된 모든 보고서를 실제 사이트로 열고 이동·정렬·크기 조절 |

사용 흐름은 **DART 필터 설정 → 보고서 목록 수집 → `data/reports.json` 저장 → 캔버스에서 보고서 비교**입니다. 두 앱을 동시에 실행할 필요는 없습니다.

## 빠른 시작

Node.js 22 이상과 인터넷 연결이 필요합니다. SSH로 저장소를 받는 경우 다음 명령을 사용합니다.

```powershell
git clone git@github.com:qqjjw/report_extractor.git
cd report_extractor
npm ci
npm start
```

수집 앱에서 목록을 만든 다음 별도 터미널에서 캔버스를 실행합니다.

```powershell
cd report_extractor\report-canvas
npm ci
npm start
```

두 번째 명령의 경로는 저장소의 상위 폴더에서 시작하는 예시입니다. 이미 저장소 루트에 있다면 `cd report-canvas`만 실행하세요. 의존성은 **각 앱 폴더에서 따로 설치**해야 합니다. 설치 후 루트 `start.cmd`는 수집 앱, `report-canvas/start.cmd`는 캔버스 앱을 실행합니다.

새로 복제한 저장소에는 개인 수집 데이터가 없습니다. 먼저 수집 앱에서 목록을 저장하거나 기존 `reports.json`을 루트의 `data/`에 복사하세요.

## 1. DART 보고서 목록 수집

1. 루트에서 수집 앱을 실행하고 왼쪽 DART에서 회사명, 기간, 공시 유형과 최종보고서 등의 조건을 직접 설정합니다.
2. **조회건수를 기본 15건에서 100건으로 변경**합니다.
3. 앱 상단의 **보고서 추출 OFF**를 눌러 **ON**으로 바꾼 다음, DART 사이트의 **검색** 버튼을 누릅니다. 이미 검색했다면 ON 상태에서 다시 검색하세요.
4. 오른쪽에서 공시대상회사·보고서명·접수일자·보고서 링크와 수집 건수를 확인합니다. `[기재정정]` 같은 표시는 유지됩니다.
5. 결과가 여러 페이지라면 ON 상태에서 다음 페이지로 이동합니다. 결과는 누적되고 접수번호가 같은 보고서는 중복 제거됩니다.
6. 수집을 끝내려면 추출을 OFF로 바꿉니다. 목록은 그대로 유지됩니다.

**조회건수는 한 번의 응답에 포함되는 보고서 수입니다.** 기본값이면 페이지당 최대 15건, 100으로 바꾸면 최대 100건을 수집합니다. 전체 결과가 100건을 넘으면 다음 페이지도 직접 열어야 합니다. 자동 페이지 이동은 구현하지 않았습니다.

현재 대상은 회사명 검색 등에서 사용하는 `/dsab007/detailSearch.ax` 응답입니다. 전체 통합검색처럼 다른 주소를 사용하는 검색 방식은 수집되지 않을 수 있습니다.

### 목록 편집과 화면 배율

| 기능 | 동작 |
| --- | --- |
| 보고서 링크 열기 | 기본 브라우저에서 원문을 엽니다. 버튼에 마우스를 올리면 주소가 표시됩니다. |
| 삭제 | 현재 목록에서 제거합니다. 다음 검색에 나오면 다시 추가됩니다. |
| 전체 비우기 | 목록을 비우고 빈 상태를 저장합니다. |
| DART 다시 연결 | DART를 다시 엽니다. 검색 조건은 초기화되지만 수집 목록은 유지됩니다. |

DART 자체 팝업은 별도 창으로 열릴 수 있습니다. 왼쪽 DART 화면을 먼저 클릭한 뒤 다음 기본 단축키를 사용할 수 있습니다.

| 단축키 | 동작 |
| --- | --- |
| `Ctrl + -` | 축소 |
| `Ctrl + 0` | 100%로 복원 |
| `Ctrl + Shift + =` (`Ctrl + +`) | 확대. 키보드에 따라 `Ctrl + =`도 사용 가능합니다. |

수집 앱에는 별도 배율 버튼·마우스 휠 확대·배율 저장 기능이 없습니다.

## 2. 보고서 무한 캔버스

캔버스는 시작할 때 **루트 `data/reports.json`을 읽어 모든 보고서를 가로 한 줄로 엽니다.** 실제 사이트이므로 목차와 본문을 클릭·스크롤할 수 있습니다. 기본 카드 크기는 1,000×800이며, 화면 밖의 보고서도 계속 열어둡니다.

| 조작·버튼 | 동작 |
| --- | --- |
| 빈 공간 드래그 | 캔버스를 상하좌우로 이동 |
| 제목 표시줄 드래그 | 해당 보고서를 자유롭게 이동 |
| 보고서 오른쪽 아래 손잡이 | 카드 크기 조절. 최소 480×360 |
| 이 크기를 전체에 적용 | 해당 카드의 너비·높이를 모든 보고서에 적용. 위치는 유지 |
| 나란히 정렬 | 현재 순서와 개별 크기를 유지해 가로 한 줄로 배치하고 첫 보고서로 이동 |
| 기간 ↑ / 기간 ↓ | 보고서명의 `(2025.12)` 같은 대상 기간을 기준으로 오름차순·내림차순 정렬 |
| − / + / 100% | 캔버스 배율을 25~150% 범위에서 조절·초기화 |
| 목록 새로고침 | JSON을 다시 읽고 모든 사이트를 처음부터 다시 열며 배치·크기·배율 초기화 |
| 다시 열기 | 특정 보고서를 처음부터 다시 로드 |

기간 정렬은 **접수일자 기준이 아닙니다.** 같은 기간은 원본 JSON 순서를 유지하고, 기간을 읽을 수 없는 보고서는 끝에 배치합니다. 크기 일괄 적용 후 겹치면 나란히 정렬을 누르세요. 사이트 안의 휠은 본문 스크롤이며 캔버스 배율 버튼과 구분됩니다.

수집 앱에서 JSON을 바꿔도 캔버스에는 자동 반영되지 않습니다. **목록 새로고침**을 눌러 반영하세요. 파일이 없거나 잘못된 경우 현재 열린 화면을 유지하고 오류를 표시합니다. 배치·크기·배율은 저장하지 않으며 실행할 때마다 초기 상태로 시작합니다.

사이트는 최대 3개씩 동시에 로드하고 완료된 사이트는 계속 유지합니다. 로드 중에는 목록 새로고침 버튼이 비활성화됩니다. 보고서가 많으면 첫 로딩 시간과 메모리 사용량이 증가합니다. 자세한 내용은 [캔버스 앱 README](report-canvas/README.md)를 참고하세요.

## 데이터 저장과 공유

수집 앱은 수집·삭제·비우기마다 `data/reports.json`에 마지막 상태를 저장하고 재실행 시 복원합니다. 토글은 매번 OFF로 시작합니다. 캔버스는 이 파일을 읽기만 하며 수정하지 않습니다.

```json
{
  "version": 1,
  "reports": [
    {
      "rcpNo": "20220816001433",
      "url": "https://dart.fss.or.kr/dsaf001/main.do?rcpNo=20220816001433",
      "reportName": "[기재정정]사업보고서 (2021.12)",
      "companyName": "코웨이",
      "receivedDate": "2022.08.16"
    }
  ]
}
```

다른 컴퓨터로 목록을 옮길 때는 `reports.json`을 별도로 복사하세요. `data/`, 두 앱의 `node_modules/`, 검증용 `work/`는 Git에서 제외합니다. 손상된 저장 파일은 수집 앱에서 덮어쓰지 않습니다.

## 사용 중 문제 해결

| 증상 | 확인·조치 |
| --- | --- |
| 수집 결과가 15건에서 끝남 | DART 조회건수를 100으로 바꾸고 ON 상태에서 다시 검색 |
| 검색해도 수집 안 됨 | 추출 ON 여부, 회사명 검색 방식, 대상 검색 응답 확인 |
| 수집 앱 DART 접속 실패 | 자동 재시도 후에도 실패하면 DART 다시 연결. 일반 브라우저 접속 확인 |
| ERR_EMPTY_RESPONSE | 두 앱 모두 요청에서 앱 이름·Electron 제품명을 제거합니다. 최신 코드로 완전히 재실행 |
| 캔버스 파일 없음 | 수집 앱에서 목록 생성 또는 루트 data/에 기존 reports.json 복사 |
| 캔버스 목록이 이전과 같음 | 로드 완료 후 목록 새로고침. 열린 모든 사이트가 처음부터 다시 로드됨 |
| 보고서 하나만 접속 실패 | 해당 카드에서 다시 열기. 다른 보고서는 계속 사용 가능 |
| 카드가 겹치거나 화면 밖에 있음 | 나란히 정렬, 배율 축소, 빈 공간 드래그 사용 |
| 저장 실패 | 수집 앱 폴더 쓰기 권한·디스크 여유 확인 |
| 저장 파일 손상 | 앱 종료 후 파일 백업·수정 또는 이름 변경 후 재실행. 옮기면 수집 앱은 빈 목록으로 시작 |
| 수집용 디버거 연결 끊김 | 앱 재실행. DART 개발자 도구를 열면 연결이 끊길 수 있음 |

현재 두 앱은 목록 수집·편집·저장과 다중 보고서 열람을 지원합니다. **본문 데이터 추출·데이터 묶기·Excel 내보내기는 아직 구현하지 않았습니다.**

## 테스트와 실제 실행 확인

루트의 `npm test`는 하위 캔버스 테스트까지 발견해 총 16개를 검사합니다. 캔버스만 검사하려면 두 번째 명령을 사용합니다.

```powershell
npm test
npm --prefix report-canvas test
```

수집 앱 테스트 12개와 캔버스 테스트 4개가 있습니다. 실제 DART 수집과 삼성전자 보고서 30개 로드, 캔버스 드래그·크기·배율·정렬·새로고침도 확인했습니다. 테스트 코드는 실행에 필수는 아니지만 변경 후 기존 동작을 확인하는 데 사용합니다.

아래 유지보수 안내는 기존 파일의 상단 입력값과 처리 로직을 구분합니다. 새 설정 관리 파일이나 상시 상세 로그는 두지 않고, 상세 진단은 문제가 발생했을 때 수행합니다.

### 앱 실행과 화면

| 파일 | 역할 |
| --- | --- |
| `main.js` | Electron 앱의 시작점입니다. 창과 DART 화면을 만들고 응답 수집, 목록 관리, 저장 및 화면과의 통신을 연결합니다. |
| `preload.js` | 화면에서 사용할 수 있는 목록 조회·추출 토글·삭제·재연결 등의 통신 기능을 제공합니다. |
| `index.html` | 앱 상단 버튼과 오른쪽 수집 목록 영역의 HTML 구조입니다. 왼쪽 DART는 별도의 웹 화면으로 표시됩니다. |
| `renderer.js` | 수집 목록과 상태 메시지를 화면에 표시하고 버튼 클릭을 처리합니다. |
| `style.css` | 앱 화면의 배치, 색상, 버튼과 보고서 카드의 스타일입니다. |
| `start.cmd` | 현재 폴더에서 `npm start`를 실행하는 Windows 실행 파일입니다. |

### 기능 모듈 (`lib/`)

| 파일 | 역할 |
| --- | --- |
| `lib/capture.js` | DART 검색 요청과 응답을 감지하고, 추출 ON/OFF 상태에 따라 응답 본문을 읽습니다. |
| `lib/connection.js` | DART 접속, 일시적인 연결 오류 재시도 및 검색 화면으로의 대체 연결을 처리합니다. |
| `lib/reports.js` | 검색 결과 HTML에서 보고서 정보를 추출하고 접수번호 기준으로 목록을 합쳐 중복을 제거합니다. |
| `lib/store.js` | JSON 파일 읽기, 저장 형식 확인, 순차 저장 및 임시 파일 교체를 처리합니다. 손상된 기존 파일은 보호합니다. |
| `lib/user-agent.js` | DART 요청의 User-Agent에서 앱 이름과 Electron 제품명을 제거하고 Chromium의 플랫폼·버전 정보를 유지합니다. |

### 테스트 (`test/`)

| 파일 | 역할 |
| --- | --- |
| `test/collector.test.js` | 보고서 정보 추출, 중복 제거, 삭제 후 재수집, 저장·복원 및 응답 수집 토글 처리를 검사합니다. |
| `test/connection.test.js` | 접속 재시도, 검색 화면 대체 연결, 오류 처리 및 User-Agent 변환을 검사합니다. |

`test/`는 `npm test`를 실행할 때 사용하는 개발용 검사 코드입니다. 앱 실행에는 필요하지 않지만 기능 수정 후 기존 동작을 확인하기 위해 저장소에 포함합니다.

| `.gitignore` | Git에 올리지 않을 로컬 데이터, 의존성, 검증 파일 등을 지정합니다. |
| `data/` | 현재 수집 목록인 `reports.json`과 저장 중 임시 파일을 보관합니다. 필요할 때 자동 생성되며 다른 컴퓨터로 목록을 옮기려면 `reports.json`을 별도로 복사합니다. |
| `node_modules/` | npm이 설치한 의존성이 들어 있습니다. 직접 수정하지 않으며 삭제했다면 `npm ci`로 다시 설치합니다. |
| `work/` | 접속 비교와 실제 앱 실행 검증 등에 사용한 개발용 임시 스크립트입니다. 앱 실행과 `npm test`에는 필요하지 않으며 저장소를 내려받아도 포함되지 않습니다. |
| `.git/` | Git이 커밋 이력과 원격 저장소 정보를 관리하는 숨김 폴더입니다. 앱 실행과는 관계없습니다. |


### 코드의 입력값과 처리 로직

새 설정 파일을 만들지 않고 각 기존 모듈 상단에 `입력값`을 모았습니다. 그 아래 `처리 로직`은 입력값을 사용합니다. 재무모델의 입력 셀과 계산식을 구분하듯, 먼저 실제 사이트와 입력값을 비교한 뒤 처리 코드를 살펴봅니다. 값을 수정한 뒤 앱을 재실행해야 적용됩니다.

| 파일 | 상단에서 수정할 입력값 | 처리 코드에서 확인할 부분 |
| --- | --- | --- |
| `lib/capture.js` | `TARGET_HOST`, `TARGET_PATH` | ON 상태 요청 추적 → 응답 완료 → 본문 읽기 → 표 확인·파싱 |
| `lib/reports.js` | `TABLE_SELECTOR`, `ROW_SELECTOR`, `CELL_SELECTOR`, `COLUMNS`, 링크 선택자, 보고서 주소·식별번호·날짜 형식 | HTML에서 행과 링크 읽기, 텍스트 정리, 필수값 확인, 중복 병합 |
| `lib/connection.js` | `HOME`, `SEARCH`, `MAX_ATTEMPTS`, `RETRY_INTERVAL_MS`, 재시도 대상 오류 | 접속 순서와 재시도·대체 연결 |
| `lib/user-agent.js` | `REMOVED_PRODUCTS` | 앱 제품명 제거, 실제 Chromium 버전과 플랫폼 유지 |
| `lib/store.js` | 저장 버전·기존 접수번호·날짜 형식 | 저장 파일 검증 → 순차 저장 → 임시 파일 교체 |
| `main.js` | `REPORTS_FILE` | DART 화면 생성 → 수집 연결 → 목록 처리·저장 → 화면 통신 |

예를 들어 회사명 열이 두 번째에서 세 번째로 바뀌면 `lib/reports.js`의 `COLUMNS.company`를 `1`에서 `2`로 수정합니다. **열 번호는 0부터 시작**합니다. 표 클래스가 바뀌면 `TABLE_SELECTOR`를 수정합니다. 검색 요청의 경로가 바뀌면 `lib/capture.js`의 `TARGET_PATH`를 수정합니다.

표 존재 확인인 `hasReportTable()`과 실제 파싱인 `parseReports()`는 같은 표 선택자를 사용합니다. 보고서 링크 생성은 `buildReportUrl()`로 통일했고 저장 파일 검사도 이 함수를 참조합니다. 따라서 뷰어 주소를 바꾸기 전에는 기존 `data/reports.json`의 링크와 저장 파일 검사를 함께 검토해야 합니다. 저장 계약과 기존 목록은 임의로 바꾸거나 덮어쓰지 않습니다.

### DART가 바뀌었을 때 어디를 확인할까?

| 증상·변경 | 먼저 확인할 코드 |
| --- | --- |
| DART 접속 실패 | `lib/connection.js`의 주소·접속 정책, `lib/user-agent.js`의 제품명 처리 |
| 검색해도 응답을 수집하지 못함 | `lib/capture.js`의 `TARGET_HOST`, `TARGET_PATH` |
| 표는 있지만 목록 추출이 안 됨 | `lib/reports.js`의 표·행·링크 선택자 |
| 회사명·보고서명·날짜가 잘못 추출됨 | `lib/reports.js`의 `COLUMNS`, 텍스트 처리와 형식 검사 |
| 보고서 링크·접수번호 방식 변경 | `lib/reports.js`의 URL 생성·식별 규칙, `lib/store.js`의 기존 저장 파일 검사 |
| 요청이 다른 iframe·팝업에서 발생 | `main.js`의 DART 화면과 수집기 연결, `lib/capture.js`의 응답 읽기 |
| 저장·복원 실패 | `lib/store.js`의 검증·저장 단계, `main.js`의 `REPORTS_FILE` |
| Electron 업데이트 후 동작 변경 | `package.json`, `main.js`의 WebContentsView·Debugger 호출, `lib/capture.js`의 CDP 이벤트·명령 |

선택자·열 번호·주소 변경은 입력값 수정으로 대응할 수 있습니다. 반면 다음은 처리 로직을 수정해야 합니다.

- 응답이 HTML에서 JSON으로 변경: `lib/capture.js`의 본문 해석·표 확인과 `lib/reports.js`의 파싱을 함께 변경합니다.
- 링크가 `href` 대신 JavaScript 또는 다른 속성으로 제공됨: `lib/reports.js`의 링크 읽기와 URL 생성 절차를 확인합니다.
- 다른 화면이나 프레임에서 요청 발생: `main.js`의 수집 연결과 CDP 세션 처리를 확인합니다.
- 접수번호 식별 체계나 저장 구조 변경: 파싱·중복 판정·저장 검증을 함께 검토하고 기존 파일의 호환성을 확인합니다.

### 문제 발생 시 점검 순서

1. 추출 ON 상태와 검색 방식을 확인하고 실제 요청 주소·응답 내용을 확인합니다. 필요한 경우 일반 브라우저의 개발자 도구 Network에서 회사명 검색 요청을 살펴봅니다.
2. 위 표에서 해당 파일을 찾아 상단 입력값을 실제 응답과 비교합니다. 예전 응답 예시만 보고 새 규칙을 추정하지 않습니다.
3. 입력값 변경으로 해결되지 않으면 바로 아래 처리 로직을 확인합니다. 필요한 임시 진단은 이때 수행하고 완료 후 정리합니다.
4. `npm test`를 실행하고 변경된 실제 응답에서도 필드·건수가 정확한지 확인합니다. 기존 테스트 통과만으로 새 DART 구조와의 호환성을 단정하지 않습니다.
5. **실제 `npm start` 실행 방식**에서 접속·검색·수집·재실행 복원을 확인합니다. 검증 스크립트와 실제 앱은 앱 이름 및 User-Agent 등 실행 조건이 다를 수 있습니다.

상시 상세 로그나 진단 화면은 추가하지 않습니다. 코드 주석·입력값 위치·테스트로 수정 경로를 명확히 하고, 상세 진단은 문제가 발생했을 때 수행합니다. 앱 안의 DART 개발자 도구를 열면 수집 디버거가 끊길 수 있으므로 확인을 마친 뒤 앱을 다시 실행합니다.

상세 파일 안내와 앱 사용법은 [report-canvas/README.md](report-canvas/README.md)에 있습니다. 원본 JSON을 보존하고 문제 발생 시에만 필요한 진단을 수행하는 원칙은 두 앱에 동일하게 적용합니다.
